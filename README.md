# Interactive Onboarding Platform

MVP платформы интерактивного онбординга для классифайда.

## 📖 О проекте

Платформа помогает централизовать и успростить разработку и управление онбордигов. Пропадает зависимость от конкретного
проекта, администратор в панеле управления может создавать сценарии для любого проекта и получать по ним аналитику.

### Решенная проблема

В больших продуктах пользователям сложно самостоятельно освоить все возможности интерфейса. Интерактивные онбординги
помогают провести пользователя через сложный сценарий, однако их разработка и изменение обычно требуют участия команды
разработки и выпуска новой версии продукта. Проект позволяет централизованно создавать и поддерживать интерактивные
онбординги.

### Возможности администратора

В панели управления администратора можно создавать проекты и подключать их к разным продуктам, что делает наш проект независимым от конкретного продукта. При подключение проекта создаются элементы, которые после можно использовать для создания сценариев. Внутри проекта администратор может создавать, удалять и изменять сценарии. Каждый сценарии состоит из подсказок, которые включают в себя элемент страницы, саму страницу и описание. Элементы можно добавлять, удалять, изменять и менять местами для более удобной настройки сценариев. Также внутри проекта можно посмотреть аналитику для выбранного временного промежутка для любого сценария и сразу скачать pdf с отчетом.

### Тестовый сайт

В нашем проекте реализован тестовый сайт на котором можно посмотреть как работает наш проект. В качестве пользовательского пути для демонстрации мы выбрали сценарий создания объявления, так как это один из самых распространненых сценариев с множеством шагов. На тестовом сайте создаются элементы, которые администратор может использовать для создания объявления в администраторской панели. Также тестовый сайт позволяет управлять вашим used_id, а именно дает возможность генерировать новый, чтобы имитировать заход нового пользователя и опытного пользователя, уже посмотревшего онбординг.

### Выдача онбординга пользователю

Модуль runtime предоставляет возможные сценарии для прохождения SDK на основе идентификатора пользователя и шаблона страницы. Пользователь может пройти онбординг, который он ранее не проходил на данной на странице, или проходил достаточно давно (полгода и более).


## 🧩 Что реализовано в MVP

### Backend (Go + PostgreSQL + Docker)

- Project — управление проектами и элементами интерфейса
- Scenario — управление сценариями и шагами
- Runtime — поиск подходящего сценария для SDK
- Tracking — создание сессий и приём событий
- Аналитика — получение аналитики по различным параметрам
- PDF_report — генерация pdf отчета с аналитикой
- OpenAPI 3.0.3

### Frontend (React + TypeScript)

- Админка для управления проектами и сценариями
- Редактирование шагов с привязкой к элементам интерфейса
- Публикация и управление статусами сценариев
- Просмотр аналитики и скачивание PDF-отчёта
- Тестовый сайт классифайда для проверки онбординга

### SDK / Виджет

- Встраивается на сайт через скрипт
- Показывает подсказки, привязанные к элементам интерфейса
- Отслеживает прохождение (шаги, завершение, пропуск)
- Поддерживает тестовый режим (test token)

## 🚀 Инструкция по запуску

**1. Клонировать репозиторий**

```bash
git clone https://github.com/DaniilSintsov/interactive-onboarding.git
cd interactive-onboarding
```

**2. Установка зависимостей и подготовка проекта**

```bash
cp .env.example .env
```

**3. Команды для запуска и отключения платформы**

Запуск:

```bash
make up
```

Остановка:

```bash
make stop - остановка
make down - остановка с удалением контейнеров
make clean - очиста томов (бд)
```

**4. Открыть в браузере**

- Админка: http://localhost:3001
- API: http://localhost:8080
- Тестовый сайт: http://localhost:3000

## Руководство пользователя

1. Перейдите в панель администратора http://localhost:3001
2. Введите пароль от панели администратора, на данный момент он универсальный: `il52lG866H-SBNl6TmPMEBWvLTgFBHV8`
3. После аутентификации Вас перенаправит на страницу управления проектами с уже подготовленным демонстрационным проектом, нажмите на карточку проекта.
4. На странице проекта представлены публичный ключ и информации о подключении к проекту, тестовый проект уже настроен и подключен к тестовому сайту. 
	- Кнопка "сценарии" отвечает за управление сценариями.
	- Кнопка "элементы" демонстрирует список элементов доступных для добавления к ним инструкций.
	- Кнопка "аналитика" открывает аналитику по прохождению пользователями сценариев.
5. Во вкладке с управлением сценариев можно создать сценарий по кнопке "создать сценарий". Необходимо указать желаемое название сценария, путь к странице, на которой будет проходить онбординг, для создания в тестовом режиме, оставить без изменений, желаемое описание сценария, нажать кнопку создать.
6. После создания сценария будет доступна его страница
	- Можно отредактировать название, описание, путь к странице сценария, затем нажать кнопку сохранить общие поля
	- Нажать кнопку добавить шаг, для создания нового шага онбординга
7. В меню создания шага необходимо:
	- Выбрать маршрут страницы, на которой вы хотите добавить подсказку для элементов, выбрать конкретный элемент на этой странице из доступных для добавления подсказки
	- Далее выбрать тип перехода, после взаимодействия с элементом по нажатию, или по изменению значения, или же переход будет выполняться на уровне приложения
	- Выбрать заголовок подсказки
	- Написать описание подсказки - основной текст
8. Последовательность шагов можно изменять с помощью соответсвующих кнопок с изображением стрелочек, кроме того, шаг можно отредактировать
9. После нажатия кнопки опубликовать, сценарий станет доступен пользователям и по нему начнется собираться статистика.
10. Перед публикацией имеется возможность протестировать сценарий, стастика по тестовому прохождению не будет записана.
11. Демонстрационный сайт доступен по адресу http://localhost:3000
12. В правом верхнем углу доступна кнопка "новый ID", она предназначена для симуляции нового пользователя, для прохождения онбординга от другого лица.

## 📡 API

Полная спецификация — backend/openapi.yaml

### Административные (/api/v1/)

- projects — управление проектами
- scenarios — управление сценариями
- steps — управление шагами
- analytics — аналитика
- report/pdf — PDF-отчёт

### SDK (/api/v1/sdk/)

- resolve — поиск сценария для SDK
- sessions — создание сессии прохождения сценария
- events — приём событий прохождения сценария

## 📝 Особенности реализации

- Архитектура проекта - модульный монолит
- Тестирование сценариев администратором реаловано с помощью токена для распознавания администратора
- Хранение архивных данных об удаленных сущностях проекта для полноты аналитики (soft delete)
- Защита endpoints с помощью admin_token и project_key
- Реализация трензакционных запросов к БД с помощью connection pool и прокидывание транзакции в context value
- OpenAPI-first подход — единый контракт между фронтом и беком через openapi.yaml
- Goose-миграции — управление схемой БД через код
- Единая семантика периода — период (from/to) фильтрует сессии по started_at (cohort-аналитика)
